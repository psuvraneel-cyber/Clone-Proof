# CloneProof public-repository field test

## Scope and method

This field test was planned on 2026-10-17 (IST) from CloneProof commit `f5d15f9` on the `field-test` branch, created from `main` at `2fcd8d1`. The run set contains 15 reputable public repositories and includes all required categories from the field-test brief except the unavailable TypeScript-Node-Starter repository, which was replaced before running CloneProof.

The pre-run expectations below were written before any CloneProof command was run against these repositories. Root package manifests, default branches, lockfile names, root `.env.example` presence, and default-branch GitHub Actions results were inspected through public GitHub pages/raw files and read-only `git ls-remote --symref ... HEAD`. No target repository was installed or tested on the host.

Each GitHub URL run is expected to make one unauthenticated GitHub size/visibility request. `check` is expected to clone only the shallow checkout; `verify` is expected to execute only inside CloneProof's pinned Docker profile. The network-allowed verification runs explicitly permit the target's npm install and test process to reach the internet inside that container.

### Summary

- **15 repositories** were exercised, including all eight required repositories.
- **13 had the expected high-level outcome on the first semantic run.** The two first-run false failures were Commander’s symlink fixtures and dotenv’s committed `.env` fixtures; both are documented limitations of the current security boundary rather than host execution bugs.
- **2 field-confirmed diagnostics were fixed**, each with offline regression tests and a rerun: `cb44146` for skipped npm install scripts/native modules and `8ca4fc3` for browser test tooling.
- **5 limitations are documented below.** The issue counts are intentionally not mutually exclusive: the Axios run has both the new browser diagnostic and the separate sensitive TLS-fixture limitation.
- The final local test suite after the fixes is **124 tests: 123 passed, 1 skipped** (the expected Windows symlink `EPERM` case).
- No CloneProof GitHub temporary folders remained, and `docker ps -a --filter name=cloneproof-verify` returned no containers.

## Known limitations

1. **Committed test secrets/fixtures are intentionally omitted.** The staging policy excludes `.env`, `.pem`, `.key`, `.p12`, `.pfx`, and `.crt` files even when a repository commits them. Dotenv’s test suite needs `.env` fixtures and Axios needs committed TLS fixtures, so those runs can be false failures. Relaxing this policy would risk copying real credentials; this remains documented rather than weakened.
2. **Symlink-dependent test suites are not reproduced.** CloneProof does not follow or stage symlinks. Commander’s two failing subtests require executable symlink fixtures; the Windows host also cannot run the integration symlink test because creation returns `EPERM`.
3. **Browser binaries are not installed.** The pinned image contains Node but no Playwright/Chromium browser. `BROWSER_TESTS_DETECTED` now explains this condition, but CloneProof does not download or execute browser installers.
4. **Lifecycle/install scripts remain disabled.** Native modules such as bcrypt can fail after `npm ci --ignore-scripts`; `INSTALL_SCRIPTS_SKIPPED` now names the affected packages and the test failure explains the likely cause. CloneProof intentionally does not enable those scripts.
5. **The image must be prepared explicitly.** The field run initially hit `DOCKER_IMAGE_UNAVAILABLE` until the exact digest was pulled manually. This is consistent with `--pull=never`; the final reruns passed once the image was present.
